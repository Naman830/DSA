## The short version

1. **Constraints tell you the answer.** `n ≤ 10⁵` means `O(n log n)` — say that out loud before you code (→ file 02).
2. **You're scored on four axes**: problem solving, coding, verification, communication. Silence blanks three of them (→ file 01).
3. **Working brute force > half-written optimal.** Always (→ file 01).
4. **Dry-run your own code before saying "done".** Most candidates skip verification entirely (→ file 03).
5. **Retention, not solved-count.** A problem counts only when you can re-derive it from a blank file a week later (→ file 04).
